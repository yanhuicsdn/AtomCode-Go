## 模型验收现状

用户完成 AtomGit 登录后，真机真实模型请求失败。源码检查确认所有 driver 共用的 provider factory 返回 `SourceBuildGatewayUnsupported`：公开仓库没有官方 CodingPlan 的闭源请求签名实现。登录凭据存在与可调用官方模型是两个独立条件。

用户明确选择暂不配置兼容模型服务，先交付 APK 并标注模型未通过。当前构建应使用自有兼容模型 API。真实模型流式生成、模型驱动的工具审批/拒绝、取消和完整对话恢复尚未验收通过。模型测试不会打印凭据、连接 URL、原始模型响应或工具内容。

## 补充宿主验收

当前 APK 要求 ZIP 中央目录完整，并在提交项目之前核对条目大小与 CRC。压缩输入及展开内容各限 2 GB，导入需为两者预留临时空间。新增两项截断回归在旧实现上失败，在修复后通过。

两台设备均通过 6 项隔离存储检查：真实内置环境安装、取消回调后保留旧指针/主目录、注入零可用空间预检、已安装引擎损坏检测与修复、归档往返（UTF-8/空目录/执行位）和截断/路径穿越归档拒绝。测试只使用可删除的缓存根，不接触用户主目录；不能据此声称实际磁盘写满或强杀恢复已通过。

仅在本任务模拟器中临时禁用 WebView 组件：应用进程保持存活，显示原生初始化失败/升级说明，界面无 WebView 节点，组件随后已恢复。最低语法目标为 Chromium 99；旧/未知版本规则另有 JVM 测试，不能替代 Android 8 实机证据。

真机通过 5 项局部布局检查。模拟器首轮横屏检查失败，缺少细分观测；补充受控诊断且保持通过条件不变后，连续两次通过 5 项检查。首次失败保留为尚未解释的间歇现象。专项只覆盖 Activity 重建、同一运行代际、输入框可见性和临时长文本滚动，不代表草稿持久化或全部键盘/旋转组合已验收。

经校验输入生成的源码清单包含 117 个 Ubuntu 二进制包（82 组源码包/版本）及 3 个 Termux 原生组件，反映实际覆盖版本而不盲信 Base 中的旧 dpkg 状态。完整对应源码归档尚未交付。Node 构建预检修正为 22.12+。本轮未修改 Rust 引擎、Cargo 清单/锁或 Rust 门，沿用此前对应基线证据，重跑受影响的 Android/Python 检查。

宿主审计待办：成功重装后尚未回收旧运行环境代际；就绪校验覆盖 daemon，未覆盖全部 Linux 文件。其他 Linux 文件损坏的恢复行为仍需专项复现，确认后修复。

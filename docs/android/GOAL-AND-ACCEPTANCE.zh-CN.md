# AtomCode-Go 最终目标与验收标准

状态：验收基线，实现进度和证据见 [验收记录](VERIFICATION.zh-CN.md)，不代表全部最终验收通过。引擎基线为 AtomCode `c4a2fbfceb5ee99907d875d3b6ec604a495cc219`，参考 dsh-Go `cf2f7c861e1098661a3a2039b3a4cb1633790102`。实际交付时应记录新的源码、依赖和产物版本。

## 最终目标

交付可侧载的 Android APK：用户在 ARM64 Android 8.0 及以上手机上无需 root、Termux、电脑或远程 AtomCode 服务器，即可安装本地运行环境、打开 AtomCode、配置模型、在手机的工作区中对话、读写代码和运行命令。AtomCode 引擎和工作区在手机上；模型请求仍需网络以及用户自己配置的模型服务和凭据。用户数据在应用私有目录内，卸载应用会删除它们，除非事先导出。

方案参考 dsh-Go 的 PRoot + Linux 用户空间：Android 宿主管理安装、进程与界面；Linux 用户空间内运行 AtomCode，复用上游 daemon、coding runtime 与 WebUI，避免另建 agent 或会话所有者。首版以 arm64-v8a 为必须交付目标，x86_64 模拟器支持应单独构建验证，不得以模拟器代替 ARM64 真机验收。Linux 二进制在 PRoot 中的兼容性仍须通过实测证明。

## 验收条件

以下条目全部通过并保留测试记录后，才能称为最终验收通过；测试须注明设备型号、Android 版本、ABI、APK 哈希、网络和模型配置，敏感信息不得进入记录。

1. **可复现交付**：从固定版本源码和校验过的依赖构建 APK，包含正确架构的 PRoot、Linux 用户空间和带已构建 WebUI 的 AtomCode；记录依赖版本、摘要、许可证与源码获取方式。干净环境按文档可重建并安装，签名方式及升级策略明确。
2. **安装和启动**：在受支持的 ARM64 真机上全新安装，首次启动显示空间需求和进度；安装中断、空间不足、损坏或校验失败时显示原因，重试可恢复，不误报成功、不破坏已有工作区。成功后可启动、停止、重启；无 root 和外部服务器。
3. **本机执行**：通过进程和网络证据确认引擎在手机本机运行、仅绑定回环地址；WebUI 可访问，设备断网时已安装环境仍可启动并操作本地文件，在线模型请求按配置发出。禁止以远程服务冒充本机执行。
4. **安全与认证**：每次启动使用不可预测 token，现有 daemon 认证开启，未认证请求返回拒绝；UI 成功完成 token 到 HttpOnly Cookie 的交接，其他应用和网页无法借无认证回环接口执行操作。WebView 仅信任指定本地来源，外部导航、文件选择与上传边界明确。凭据不出现在日志、构建产物或 Android 备份中。须检验端口抢占、伪造本地服务与跨来源请求，不得把仅绑定回环当作认证。
5. **核心工作流**：配置兼容的模型及凭据后创建会话，流式收到回复；在应用私有工作区读取、创建、修改文件，审批和拒绝工具调用，执行命令并展示结果；检查文件真实内容与命令退出状态。取消运行能终止操作并给出明确结果。模型服务失败时可读地提示且不伪装成功。
6. **会话与数据**：正常退出、重新打开和进程被系统终止后，会话及工作区内容仍在，可恢复会话；升级运行环境后保留用户数据。测试升级中断、失败回滚和存储不足；提供工作区导入导出，且不允许路径穿越或静默覆盖已有文件。
7. **手机可用性**：在手机竖屏与横屏下检查输入法、滚动、长文本、代码块、审批、文件选择和终端；交互元素不被键盘或系统栏遮挡，触控可用。重建 Activity 或后台返回时不丢失已保存内容，服务死亡时界面显示状态并可恢复。
8. **生命周期**：启动、运行和停止的状态一致；前台服务与通知符合目标 Android 版本要求；显式停止后进程退出。记录后台限制与系统强制停止行为，不承诺 Android 不保证的常驻能力；启动失败、端口冲突和进程意外退出均能诊断和重试。
9. **网络和系统兼容性**：DNS、HTTPS 证书、IPv4/IPv6 及设备休眠恢复经实际设备验证；至少覆盖 Android 8 和当前目标 Android 版本、不同厂商设备，另测 16 KB 页大小设备或明确记录未支持。用户无网络时错误可见。
10. **验证证据**：运行上游相关编译、格式和测试门，运行 Android 单元、安装与端到端测试；提供安装包、校验值、构建命令、设备测试结果及已知限制。不得将编译成功或静态检查称为真机验收。

## 实施边界与顺序

- 基于当前上游 daemon 的 `ATOMCODE_DAEMON_TOKEN` 和 `/?token=` Cookie 交接设计宿主认证；启动前必须防止抢占和伪造服务，避免将 token 发送给未验证的监听者。评估 Unix 域套接字或其他经过验证的进程绑定方案，再实现并测试。
- 先建立可校验的 Linux ARM64 构建与 PRoot 启动验证，再实现具备失败恢复的安装器、进程管理和 WebView。运行环境升级必须先保护用户数据；不直接复制 dsh-Go 品牌或素材。若复制其代码，应遵守 AGPL-3.0 及所含第三方组件的授权义务；采用独立实现也需遵循实际分发依赖的许可证。
- 保留 AtomCode 的单一 coding runtime 与会话存储，不修改其持久化格式来适配宿主。Android 只负责安装、启动、界面、设备集成及错误呈现。
- 执行测试从本机自动化、模拟器到 ARM64 真机逐级推进。缺少工具链、实际模型服务或设备时，记录阻塞和未通过项，不把计划或样例包装成成品。
